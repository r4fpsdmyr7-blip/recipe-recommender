## 3. 唯一未决项：CL-02（实现语言）

用户原话：**「搭建语言使用计算机标准语言，输出语言为用户指定语言」**。

后半句已明确并落地（D-05）；前半句存在三种可能口径：

| 口径 | 含义 | 待确认内容 |
|------|------|------------|
| **A** | 指**实现语言**应采用某种有正式标准 / 生态成熟的主流编程语言 | 具体是哪一种？TypeScript (ECMAScript / ECMA-262)、Python、C# (ECMA-334)、C++ (ISO/IEC 14882) 或其他？ |
| **B** | 指**内部构建表示**采用与自然语言解耦的机器标准标识，从而使输出语言可自由切换 | 此层已作为不可协商架构约束落地（FR-041、P-11），无需二选一 |
| **C** | A 与 B 兼指 | 仍需确认 A 的具体语言 |

**本轮采取的措施**：不猜测、不写死实现语言、不产出 `plan.md`；同时把口径 B 独立固化，因此其余规格与立项工作不受阻塞。

> 待用户确认后：关闭 CL-02 → 产出 `constitution.md` 与 `plan.md`（技术选型 / 架构 / 接口 / CI 矩阵）。

## 4. 由决策引出的新增约束（摘要）

1. **i18n 是架构约束，不是翻译功能**：规则引擎只处理 Canonical ID；语言包承载全部人可读字符串；翻译不得依赖在线服务或 LLM。
2. **切换语言不改变任何数值**：营养计算、去重指纹、台账、时间线护栏与计划语义必须与语言无关（FR-044）。
3. **区域策略可追溯**：默认按声明的国籍 → 居住地解析，用户覆盖优先，未匹配显式回退；禁止通过 IP / 定位 / 静默推断（FR-045/046）。地区码按 ISO 3166-1，中国香港 / 中国澳门 / 中国台湾为中国的地区级选项。
4. **历法可插拔**：精确节气流程只在解析为 `solar-terms` 时适用；通用季节历同等遵守「年计划刷新、下层只读、失败 FALLBACK」。
5. **示例数据零真实个人信息**：两份合成档案，标注虚构性；CI 静态扫描防止 `diet-plan/` 数据误入库。
6. **许可边界**：代码 GPL-3.0；第三方数据 Unlicense / CC0 / 用户自建；不得复制受版权保护的指南原文或图表。
